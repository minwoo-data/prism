# prism-ideas: design proposal

Status: approved 2026-10-14 (D1 to D5 as recommended), building S1.
Origin: your idea from the golmok session (2026-10-14): "prism only judges. Could a companion also propose new ideas, and evaluate them together?"

## 1. Why

prism answers "is this wrong?" and stops there. The golmok case shows the gap: a judgment-only review ends at "7-Eleven AI Analyst scores low." The useful next step was a different route, body-based pre-judgment (it became PRD-6). Nothing in prism produces that kind of output today.

The closest thing prism has is the Improvement lens (`--include-improvements` for code, on by default in the design lens set). It has three problems:
- Its output is a free-form line ("current -> proposed -> rationale") with no grounding rule, so it can produce generic advice.
- It goes through the Evidence pass, which is built to confirm defects, not to judge whether an alternative is worth doing.
- There is no rubric. Cost, risk and what the idea replaces are not asked for.

## 2. What it is

A new skill, `prism-ideas`, inside the prism plugin.
- **Standalone:** `/prism-ideas <target> [--context <file>]...` when you only want ideas, for example before writing a PRD.
- **Companion:** `/prism`, `/prism-all` and `/prism-codex` run it automatically after the Evidence pass (Pass 4). `--no-ideas` turns it off.
- **It replaces the Improvement lens.** One channel for alternatives, not two.
- **Ideas never mix with defects.** They get their own report section and their own JSON array, and never enter defect counts, the action order, degraded angles or any gate.

## 3. Flow

```
Pass 1 discovery (5 defect lenses) -> triage -> Pass 2 Evidence -> checked.json
                                                                       |
Pass 4 ideas (new)                                                     v
  4a  Propose   1 idea agent per engine, 3 idea lenses, <= 3 ideas per lens
                input: target + checked.json (SUPPORTED / REPRODUCED findings) + --context files
  4b  Gate      verify-ideas.js (script): format, cap, grounding. Fails -> dropped, counted
  4c  Check     an independent checker rates each surviving idea KEEP / WEAK / DROP
                (prism-all: each engine's ideas are checked by the OTHER engine)
  4d  Rank      script: deterministic order, then the IDEAS section of the report
```

Standalone mode skips Pass 1 to 2. Grounds must then be quotes, because there are no findings to cite.

## 4. The three idea lenses

One agent per engine runs all three, so the target travels once per engine instead of three times. Each lens may return at most 3 ideas.

| Lens | Question | Example of a good idea |
|---|---|---|
| **class** (fix the class) | Several findings share a cause. What structural change removes the whole class instead of patching each one? | "These 4 findings are rules that live only in prompt text. Move them into the script, and all 4 become impossible." |
| **route** (a different route) | Is there another mechanism that reaches the same goal and sidesteps the problem? | golmok: "Keyword scoring under-rates good postings. Pre-judge from the posting body first, then score." |
| **subtract** (remove or reuse) | What can be deleted, merged, or replaced by something that already exists in the repo or data? It must name the existing thing with `file:lines`. | "This parser duplicates `parse-findings.js`. Reuse it." |

## 5. Output contract (both engines, one source)

The contract lives in one file, `templates/ideas-contract.md`; the checker's format lives the same way in `templates/idea-check-contract.md`. Both engines get the same prompt: the Codex call goes through `codex-run.sh ideas`, and the Claude agent prompt is generated by `codex-run.sh ideas-prompt` (same bytes minus the sandbox preamble). This is the lesson from the triad 0.3.0 review, where the Claude side's output format lived only in a deleted template.

```
<<<PRISM-IDEAS v1>>>
{"lens":"route","title":"Pre-judge from the posting body","problem":"PRISM-004: keyword score under-rates strong matches","grounds":["PRISM-004","<scores file>:118 — \"score\": 62"],"proposal":"...","replaces":"keyword-only first pass","cost":"M","cost_note":"one new engine file + a sheet column","effect":"strong matches stop landing below the cut; measurable on the 177 cached postings","risk":"a second judgment can disagree with the score; show both"}
<<<END>>>
```

One JSON object per line. The rubric fields are the five you named:

| Field | Meaning | Rule |
|---|---|---|
| `problem` | Which real problem this solves | required, must match one of the grounds |
| `replaces` | What it replaces or removes | required, `none` allowed (marked additive, ranked lower) |
| `cost` + `cost_note` | Effort | `S` / `M` / `L` + one line |
| `effect` | Expected effect, and how you would know it worked | required |
| `risk` | What could go wrong, and the mitigation | required |

## 6. Code gates (`verify-ideas.js`)

These are rules a script enforces, not instructions to the model:

1. **Grounding.** Every idea needs at least one valid ground:
   - a finding ID whose status in `checked.json` is SUPPORTED or REPRODUCED (SUSPECTED and REJECTED do not count), or
   - `file:lines — quote`, where the quote actually appears at those lines. This uses the same matcher as `verify-evidence.js`, and works for code, data files and `--context` files.
   A quote may span at most 40 lines, must be at least 8 characters, and may never come from a credential file (`.env`, keys, tokens). No valid ground -> `UNGROUNDED`, dropped. A `problem` that names a finding which is not one of the idea's valid grounds is also `UNGROUNDED`.
2. **Cap.** The first 3 valid ideas per lens per engine are kept. The rest are `OVER_CAP`.
3. **Format.** Required fields, enums (`lens`, `cost`), length limits. Bad lines are counted, never silently lost.
4. **Ranking** (deterministic): checker KEEP before WEAK -> cross-model before single -> replaces something before additive -> cost S < M < L -> grounded in REPRODUCED > SUPPORTED > quote only.
5. **Checker honesty.** A DROP that says "this already exists" or "this conflicts with X" must quote X. If the quote does not verify, the verdict falls back to WEAK with a note. The idea is not dropped on an unverified claim.

Data that is not a file (for example sheet numbers) has to be exported and passed with `--context`. Then the script can check the quote.

## 7. Evaluation: the check step (4c)

The proposer's own rubric is self-assessment, so an independent checker rates every gated idea. It runs in batches of 8, like the Evidence pass, and sees the ideas and their grounds but not the proposer's reasoning. For each idea:
1. Does the proposal actually address the cited problem?
2. Does something in the repo already do this, or conflict with it? It must search before claiming, and quote what it finds.
3. Are the cost and risk honest? It may adjust them with one sentence.
4. Verdict: `KEEP` / `WEAK` (partly addresses it, or cost underestimated) / `DROP` (does not solve it, already exists, or conflicts).

It never invents new ideas. When ideas are grouped, the group's verdict is the worst verdict among its checked members, so agreement never overrides a checker's finding. In `/prism` the checker is a separate Claude agent. In `/prism-all` it is cross-checked: Codex checks Claude's ideas and Claude checks Codex's. Ideas both engines proposed are tagged `cross-model` and checked by the `--verifier` engine.

## 8. Report and JSON

```
## IDEAS (alternatives, not defects; not in the action order)
Ideas: 14 proposed -> 9 grounded -> 6 keep, 2 weak, 1 drop  (ungrounded 3, over cap 2)
- IDEA-1 [cross-model | route | cost M | KEEP] Pre-judge from the posting body
  problem: PRISM-004 · replaces: keyword-only first pass · effect: ... · risk: ...
  grounds: PRISM-004 (SUPPORTED), <scores file>:118 — "score": 62
```

JSON: `prism-report.json` gets an `ideas: [...]` array next to `findings`, plus `meta.ideas: {proposed, grounded, keep, weak, drop, ungrounded, over_cap, engines}`. `findings`, `meta.counts`, `degraded_angles` and the planned merge-gate fields do not change.

## 12. Decisions for you

| # | Decision | Recommended | Alternative |
|---|---|---|---|
| D1 | Where it lives | **`prism-ideas` skill in the prism plugin.** It reuses prism's quote matcher, Codex runner and records, and ships with prism. | A separate plugin. More independent, but it would have to copy all of that. |
| D2 | The Improvement lens | **Replace it with the idea pass.** One channel for alternatives. | Keep both. They would overlap and confuse the report. |
| D3 | When ideas run | **After the Evidence pass**, so ideas only target confirmed problems. Costs about 2 min on prism-all. | In parallel with Evidence, with no added time. Ideas aimed at candidates that later get rejected are wasted, and the cap of 3 makes that costly. |
| D4 | Default | **On for prism, prism-all and prism-codex**; off for `--quick` and gate runs; `--no-ideas`. | On only for prism and prism-all. |
| D5 | Version order | **Ideas = prism 0.5.0.** The merge-gate S0 (prism report contract) becomes 0.6.0, and I update the local ddaro spec. | Merge-gate S0 first, ideas = 0.6.0. |

## 14. Out of scope

- Ideas for triad (document writing quality). Can be added later the same way.

- Linking the same idea across runs (fingerprints for ideas). Later, if repeats become noise.
